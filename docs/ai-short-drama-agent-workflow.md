# AI 短剧执行型 Agent 流程

## 设计结论

导演工作室采用“1 个代码编排器 + 4 个执行 Agent”，不再把每一类专业检查包装成一次独立文本补全。专业职责仍然保留，但只有产出被下游消费、能够调用工具或拥有否决权的阶段才称为 Agent。

## 总导演编排器

总导演是持久化状态机，不是普通聊天角色：

- 管理项目状态、阶段依赖、进度、失败和最终交付。
- 阻止未通过结构校验的故事或分镜进入媒体生成。
- 将视频、语音、字幕、合片和质检结果保存到项目。
- 任一媒体任务或质检失败时将项目标记为失败，不伪造“已完成”。

## 四个执行 Agent

| 阶段 | 类型 | 真实输入 | 可消费交付物 / 工具行为 |
| --- | --- | --- | --- |
| 故事 Agent | 文本模型 | 故事创意、时长、画幅、用户锁定信息 | 经校验的故事 JSON：受众、主题、角色、节拍、对白和剧本 |
| 视觉 Agent | 文本/视觉模型 | 故事 JSON、视觉风格、连续性要求 | 经校验的视觉 JSON：连续性圣经、逐镜视频提示词、speaker、speech_text、voice_id |
| 媒体制作 Agent | 工具执行 | 逐镜结构化方案 | 优先保留 H3 原生声画；缺少原生音轨时调用 Speech 兜底；按对白时间窗烧录字幕并合片 |
| 质检 Agent | 工具与规则 | 实际生成的 MP4、镜头和项目元数据 | ffprobe 检查报告；验证视频轨、语音轨、字幕标记和时长，拥有最终否决权 |

## 配音与字幕规则

- 每个镜头必须包含非空 `speech_text`，否则视觉交付不通过。
- 中文台词按镜头时长限制长度，避免原生对白或兜底 TTS 被强行截断。
- `subtitle_text`、H3 原生对白指令与兜底 TTS 共用同一份文本。
- MiniMax H3 原生声画是主路径：对白、角色声线、情绪、动作音效与背景音乐由同一生成过程完成，避免二次配音造成双人声和口型脱节。
- 外部 Speech 只在视频确实没有原生音轨时兜底，兜底时不会叠加视频中的未知人声。
- 字幕文本与对白共用同一份分镜数据，并按对白起止时间烧录，保留可校正能力。
- 字幕使用 Noto CJK 字体直接烧录到视频，不依赖播放器外挂字幕。

## 项目模式

- 普通制作：完成故事与视觉规划，生成一个 4 秒、带原生声音和定时字幕的真实预览镜头。
- 一键成片：按 4/8/12 秒合法时长拆镜，逐镜生成原生声画、烧录字幕，再合成为目标时长影片；仅对无原生音轨镜头调用 Speech。

## 持久化数据

- `DirectorProject.quality_report`：最终技术质检报告。
- `DirectorProject.resolution`：用户在制作时选择的 `768P` 或 `2K` 清晰度；每个
  `VideoJob.resolution` 会固化实际提交给视频渠道的值，避免运营默认值变更影响已启动项目。
- `DirectorAgentRun.result_data`：模型或工具阶段的结构化结果。
- `DirectorShot.speech_job_id`：兜底 Speech 任务；H3 原生声画镜头为空。
- `DirectorShot.speaker/speech_text/subtitle_text`：说话人、配音和字幕正文。
- `DirectorShot.rendered_path`：已经完成混音和字幕烧录的镜头文件。

## 后续增强

- 用抽帧和多模态模型增加人物漂移、闪烁、构图及口型质量检查。
- 增加带版本号的人工修改、重跑和从指定阶段恢复。
- 按角色维护多个固定 `voice_id`，并增加 TTS 时长预测和自动语速调整。
- 复杂项目按需启用音乐、智能剪辑和发布合规阶段，不为所有项目固定增加模型调用。
