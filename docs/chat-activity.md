# 聊天执行记录

聊天等待区域每 1.5 秒查询当前请求的实际事件，完成后可展开时间线和执行日志。
从聊天创建的导演项目可展开总导演、四位执行 Agent、判断摘要、交付物、预演轮次、
镜头与媒体任务。导演卡始终读取项目最新状态，旧会话中的卡片也会刷新。

## 数据来源与边界

- `/api/v1/chat/activity?key=…` 使用当前用户与幂等键共同定位请求；
  `/api/v1/chat/runs/{id}` 同样校验所属用户，支持历史会话恢复中的请求。
- Redis 保存每个请求最近 200 条事件，24 小时过期；写入与读取均有超时保护。
  已结束的聊天将记录归档到 ChatRun 和消息 artifacts，失败时保留已创建交付物。
- 导演 worker 使用独立项目上下文，事件在结束或等待用户确认时归档到项目
  `quality_report.execution_activity`。旧项目仅显示真实的阶段状态记录，不补造历史日志。
- 事件只包含名称、状态、时间、耗时及受控描述，不转发原始服务日志、系统提示词、
  请求凭据或模型私有推理。导演判断摘要与交付物沿用已存在的用户可见输出。
- 若早期聊天只保存了文字、没有保存项目 artifacts，则无法恢复导演卡片；
  不根据文本或时间猜测关联项目。这类项目仍可从视频工作室打开。
- Pi 的“模型请求许可”表示限流校验通过，不代表该次模型响应完成；
  “Pi 执行循环完成”表示整轮响应实际返回。工具记录与业务执行结果分别采集。

## 验证

`python -m pytest tests/test_activity.py` 覆盖并发隔离、容量限制、存储故障、
用户权限查询、聊天归档与导演 worker 上下文归档。前端用真实聊天和历史导演卡验证。
