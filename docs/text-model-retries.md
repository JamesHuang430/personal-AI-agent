# 文本模型暂时故障重试

`logged_model_completion` 在单次文本请求边界执行重试，覆盖导演规划、总导演预演、
Python 聊天模型及记忆提取；不重跑已执行工具，不重提生图、语音或视频任务，
也不对整个 Pi agent 回合做重放。

- 最大 4 次请求（初次 + 3 次重试），默认等待 2/4/8 秒并附加不超过 0.5 秒的随机抖动。
- 重试连接错误、请求超时、HTTP 408/409/429 和 5xx。
- 不重试认证/权限/参数错误、已知额度耗尽及本地程序错误。
- 遵循有效的 `Retry-After` / `Retry-After-Ms`。超过 30 秒自动等待预算时结束重试，
  让用户稍后恢复，不提前重复冲击上游。
- SDK 内置重试保持关闭，每次实际请求重新通过 Redis 全局 QPS 限制。
- 每次请求单独记录耗时、真实 HTTP 状态与 `_retry` 元数据；这些元数据不发送给模型。
- 执行活动显示等待时间、当前请求序号；公共最终错误不包含上游 HTML。
- 等待使用异步 sleep，取消会立即传播，不阻塞 worker 续租。

长请求可能已在上游执行或计费，文本重试不能保证上游不重复计费。
因此这一策略不能复用到没有幂等保障的媒体提交或业务工具上。

运行 `pytest tests/test_text_model_retry.py` 验证 504→成功、连续失败上限、
认证失败、429、连接超时、取消传播、Retry-After 与每次重试的限流记账。
