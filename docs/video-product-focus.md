# 知伴视频创作：产品定位、评估与验收

## 唯一主线

在更了解用户创作喜好的前提下，更方便地生成符合用户期待的视频。
创意 → 故事 → 分镜 → 视频与声音 → 字幕 → 合片 → 技术质检 → 用户验收。
聊天、向量记忆、素材与渠道均服务这条主线，不以通用聊天平台为目标。

## 这轮评估

已有的价值是：结构化故事和分镜、真实媒体任务、原生声音/兜底配音、字幕合片、
技术检查，以及上一轮补齐的持久化任务和恢复机制。

原来的关键缺口是：导演没有读取聊天记忆；不存在可编辑的创作偏好；
用户只能在模型规划之前确认创意，无法在媒体生成前核对最终分镜；
技术检查通过被当成最终完成，缺少用户满意度反馈。
参考图数量计算出的连续性分数也不能说明实际画面质量。

## 已落地的闭环

1. **用户表达**：创意对话整理稳定的视觉、叙事、节奏、声音和受众偏好。
   剧本人物不是用户本人，角色关系不是用户个人关系，一次性设定不自动变成长期喜好。
2. **明确偏好**：工作室提供偏好编辑表单，字段可修改、清空。
   `use_memory` 控制新项目是否参考历史记忆，不是聊天存储开关。
3. **有依据的个性化**：建项目时读取明确偏好、相关向量记忆与近期创作偏好。
   过滤不相关领域、低置信度、已删除/失效记忆；最多采用六条。
   向量检索有八秒上限，失败时允许按明确偏好和近期记录继续。
4. **可追溯**：项目持久化当时的偏好、记忆来源与时间；用户能看到本次参考内容。
   本次要求 > 明确设置 > 历史记忆。生成后修改偏好不会重写旧项目。
5. **可控制的制作**：草案可编辑；新项目完成故事、视觉和导演预演后进入
   `awaiting_storyboard`。页面展示故事、逐镜画面和对白，确认请求绑定具体方案摘要。
   重复确认不会重复排队。已有项目保持迁移前的执行策略。
6. **验收与学习**：媒体技术完整性与用户满意度分别记录。
   制作台可直接播放、下载带声音和字幕的镜头成品或最终合片，专业执行记录默认折叠。
   评分、本片意见默认只属于本片；只有明确勾选且填写的长期偏好才保存为创作记忆。
   同一项目重复提交更新同一条记忆；撤回勾选后，未来项目不再使用该条记忆。
   反馈记忆即使尚无向量也参与后续创作检索。
7. **保留原作**：运行中的项目不能覆盖修改。对已规划/完成作品的修改可带着原创意
   和本片反馈新建草案，保留旧作品；这会重新规划和生成，不声称复用未修改镜头。

## 舍弃与保留

| 处理 | 内容 | 原因 |
|---|---|---|
| 移除用户入口 | 签到、积分套餐、旅行待办等通用提示 | 分散创作流程，也没有消费计费闭环 |
| 移出当前路线图 | 天气票务、支付、通用知识平台、扩展市场 | 不直接改善视频满意度或制作效率 |
| 保留 | 登录、用户隔离、运营渠道、队列与日志 | 支撑制作和运维 |
| 聚焦 | 聊天、向量记忆、图谱、素材理解 | 服务创作偏好和剧本素材 |
| 保留内部工具 | 文件、视频、配音、音乐、检索 | 可被制作流程消费，不额外主推成独立产品 |
| 暂留兼容数据/API | 历史积分、套餐和原会话数据 | 不为界面收敛做破坏性数据删除 |

## 仍需补齐，不能宣称已完成

- **逐镜修改与版本管理**：现在可编辑草案或新建一版，尚不能选择第三镜修改并保证其余镜头复用。
- **内容审片**：人物漂移、对白准确率、口型、字幕实际对齐、审美与叙事效果仍需人工判断。
  当前质检仅验证音视频轨、字幕文本/时间窗和时长等技术条件。
- **真实预算**：展示计划镜头数和需要调用媒体，不伪造供应商价格、余额或成本预估。
- **参考资产硬约束**：登记参考图并不等于供应商生成过程锁定角色；页面只展示登记率。
- **质量效果验证**：单元与数据库测试能证明流程边界，不能证明视频更符合个人喜好。
  需要同一批创意的对照生成、用户盲评和供应商实际故障恢复试验。
- **删除边界**：删除/撤回记忆阻止新项目继续检索；旧项目保留曾使用的历史快照。

## 下一轮优先级

优先做逐镜修改与版本保留，其次是结合音频转写和抽帧的内容审片，再根据真实渠道
计量补预算与成本上限。每项都应以用户交付效果验收，而不是增加 Agent 名称或数量。

## 产品验收样例

- 用户设置“复古胶片、慢节奏、轻配乐”，新项目应显示这些依据，故事/视觉/预演均收到参考。
- 同一用户本次指定“快节奏动画”，应服从本次要求，不能被历史胶片偏好覆盖。
- 用户聊剧中人物的家庭经历，不能被提取成用户自己的家庭关系。
- 文本规划完成且用户未确认分镜时，供应商视频创建调用应为零。
- 用户重复确认同一分镜，只有一个待执行制作任务。
- 用户只给一星但不勾选记忆，不新增长期偏好；明确填写偏好后，下一项目能读取。
- 修改自己的偏好、作品反馈，不能影响其他用户；修改偏好不改写旧作品。
- 成片通过技术检查后仍显示待验收；用户选择“需要修改”时不能显示“用户满意”。

## 小额真实验收

工作室支持“4 秒试片”：选择一键成片时只有一个 4 秒镜头，仍执行声音、字幕、合片和技术质检。
生产验收脚本为 `scripts/validate_creative_flow.py`，使用容器内已有配置和指定用户的临时会话，
退出时撤销会话，不输出凭证。它会真实消耗视频渠道额度，只能在用户授权后运行。

首次传入 `--user-id`、`--state-file`、`--create` 和 `--premise`，脚本在分镜确认处停止。
检查分镜后，使用同一状态文件和 `--approve` 继续；固定限制为一个 4 秒、768P 镜头。
重复运行只观察已有项目，不新建项目；创建结果不确定时停止，不自动重试付费生成。
排查失败原因后才可显式传入 `--resume` 恢复同一个项目，保留已完成的规划和媒体任务。
状态文件应放在私有、持久化目录，不得放入公开下载目录或提交代码仓库。

生成后由用户观看并评价，将用户实际提供的 `verdict`、`rating`、`notes`、`remember`、
`reusable_preference` 写入 JSON，再通过同一状态文件及 `--feedback-file` 提交。
不能用脚本编造好评或用户长期偏好。反馈接口只接受已完成且属于该用户的项目。
