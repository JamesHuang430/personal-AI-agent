# 白板产线（基础版）

新建导演项目默认 `production_mode=whiteboard`；`video` 保留既有动态视频逻辑。
数据库迁移将已有项目标记为 `video`，不会改变正在执行的老任务。

## 流程和费用

故事草案 → 文本规划与预演 → 用户确认分镜 → 每镜一幅图片 → 旁白 → 本地描线、上色、字幕 → MP4。
完整成片按约 25–35 秒一镜分段（短片可不足 25 秒）；常规试片仍是 4 秒。

- 默认从运营后台独立配置的 MiniMax 图片渠道生成图片，支持 `image-01` / `image-01-live`。
- 语音复用已有语音渠道，不自动复用其他渠道的密钥。
- 分镜待确认时可为每镜上传 PNG/JPEG/WebP（最大 12 MB、1600 万像素），该镜不再提交生图。
- 文本、生图、配音可能收费；仅本地渲染没有视频模型调用费，仍消耗服务器资源。
- 白板失败不会升级为动态视频；图片请求一旦提交但结果不明，不自动重发，以免重复扣费。
- 失败后的替代图片可重新上传并再次确认分镜；成功落盘的图片、配音和镜头在恢复时复用。

## 配置与部署

运营后台 → 图片渠道 → 新增 HTTPS 地址（默认 `https://api.minimaxi.com`）、模型与 API Key，启用。
密钥加密入库且不回显；配置保存不做付费试调用。独立检查生图权限与余额。
语音渠道必须已启用。全部上传自有图片时不要求图片渠道存在。

依赖：FFmpeg/ffprobe、Noto Sans CJK、NumPy、OpenCV headless、Pillow。
运行 `alembic upgrade head`；重新构建并部署 API、运营后台与 worker。
白板输出标准尺寸为 720×1280 / 1280×720，高清沿用项目的 1024×1792 / 1792×1024。
项目字段 `768P` / `2K` 为兼容现有渠道的档位名，界面显示白板实际像素尺寸。

## 明确限制

这是独立实现的基础渲染器，受研究 `geeklee/srt-whiteboard-animation` 启发，
并未直接集成其完整 Skills 工作流。每镜整体按照几何轮廓描线，再逐渐显色。
目前没有对象语义分割、逐对象字幕驱动顺序、遮挡保护区或 SRT 文件导入入口。
旁白字幕按文本长度估算分段时序，不是逐字强制对齐。配音较长时延长镜头，避免切断语句。
技术质检检查轨道和时长；图片一致性、讲解准确性和绘制顺序仍需人工验收。
现有动态视频的重新配音入口不支持白板项目，需新建一版。

## 验证

`tests/test_whiteboard.py` 覆盖默认值、旧项目兼容、确认门禁、成本隔离、图片校验、
不明提交防重发、字幕分段以及真实 OpenCV 编码（空白和稀疏图片）。
`tests/web/creative.test.mjs` 覆盖制作方式选择和上传入口。
`tests/test_postgres_execution.py` 的白板集成测试使用隔离 schema、测试图和合成音频，
不调用付费服务，验证上传权限、迁移兼容和真实 FFmpeg 音视频成片。
